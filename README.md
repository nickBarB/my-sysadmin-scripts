# Мониторинг ресурсов

Bash-скрипт каждые 10 секунд записывает временную метку, состояние памяти (`free -h`), дискового пространства (`df -h`) и нагрузку (`uptime`) в `monitor.log`.

## Архитектура

Мониторинг и Python HTTP-сервер работают в одном Docker-контейнере. Nginx на сервере обеспечивает HTTPS и проксирует запросы к контейнеру.

```text
HTTPS :8443 → Nginx → 127.0.0.1:18080 → контейнер :8080
```

HTTP на порту 8081 перенаправляется на HTTPS. Лог доступен по `/monitor.log` и хранится на LVM-томе в `/mnt/edu-monitor-logs/my-app`. Для учебного RAID 1 используются два файла-диска; LVM создан на третьем отдельном файле-диске.

Конфигурация systemd предусматривает автозапуск контейнера после Docker и восстановления учебного хранилища.

## Файлы

- `script.sh` — сбор показателей ресурсов.
- `entrypoint.sh` — совместный запуск мониторинга и HTTP-сервера.
- `Dockerfile` — сборка образа.
- `docker-compose.yml` — параметры контейнера, порта и тома.
- `sample_output.txt` — фактический пример работы скрипта на сервере.
- `deploy/nginx.conf` — конфигурация reverse proxy и TLS.
- `deploy/*.service` — службы приложения и хранилища.
- `deploy/storage-create.sh` и `deploy/storage-restore.sh` — создание и восстановление подключения RAID/LVM.
